# Contributing

Thank you for your interest in improving Odelis. Clear bug reports, thoughtful suggestions, documentation improvements, and code changes can all help the project grow.

## Before contributing

Before proposing a change:

1. Review the existing documentation and repository files.
2. Check the repository's existing issues and pull requests to see whether the topic has already been raised.
3. Keep proposed changes focused on a clear problem or improvement.
4. Avoid including passwords, tokens, private information, or other secrets in issues and pull requests.

## Reporting a bug

When opening a bug report, include the information needed to understand and reproduce the problem:

- A concise description of the issue.
- The steps needed to reproduce it.
- What you expected to happen.
- What actually happened.
- Relevant browser or environment details, when applicable.

Do not include personal or sensitive information in screenshots or logs.

## Suggesting an improvement

For a feature request, explain:

- The problem you want to solve.
- Why it matters to users.
- How you imagine the improvement working, if you have a proposed approach.

A clear problem statement is more useful than prescribing a complicated solution immediately.

## Contributing documentation

Documentation improvements are welcome. Aim for writing that is accurate, concise, and consistent with the rest of the site.

When documenting a feature, describe the behavior that currently exists. Clearly distinguish implemented functionality from ideas that may be considered in the future.

## Contributing code

Before submitting a code change:

1. Keep the change focused and consistent with the existing project.
2. Test the affected behavior.
3. Update relevant documentation when behavior changes.
4. Review your changes for accidental edits or sensitive information.
5. Open a pull request with a clear explanation of the change.

Follow any repository-specific contribution instructions and review requirements.

## Pull requests

A helpful pull request should explain:

- What changed.
- Why the change was needed.
- How it was tested.
- Any limitations or follow-up work.

Be open to feedback and make revisions where appropriate.

## Project policies

Follow the policies and contribution requirements published in the relevant Odelis repository. These instructions are intended to supplement, not replace, repository-specific rules.

Thank you for helping make Odelis clearer, more useful, and easier to maintain.
